# 需求文档

## 简介

为 LookLift 建立受控 Connector、MCP 与外部模型 Provider 集成层，统一连接配置、来源证明和用户确认流程。

## 需求

### 需求 1 - 连接器注册

**用户故事：** 作为用户，我想要连接照片目录、Look 库、XMP、相机元数据和模型 Provider，以便把工作资料纳入调色流程。

#### 验收标准

1. 当注册 Connector 或 MCP 时，系统应该校验 manifest、协议版本、能力和数据接收方。
2. 当连接未获授权或凭据失效时，系统应该阻止读取并返回可操作错误。

### 需求 2 - Source Packet 与提案

**用户故事：** 作为用户，我想要先审阅外部资料如何影响项目，以便避免隐式写入记忆或模板。

#### 验收标准

1. 当 Connector 返回事实、引用或建议时，系统应该封装为带来源和摘要的 Source Packet。
2. 当 Source Packet 试图写入 Memory、ProjectContext、Skill、Template 或 Reference 时，系统应该先生成 Proposal，未经用户确认不得应用。

### 需求 3 - Provider 数据边界

**用户故事：** 作为隐私敏感用户，我想要知道模型收到什么数据，以便安全选择 Provider。

#### 验收标准

1. 当调用外部模型时，系统应该展示 Provider、模型、数据接收方和脱敏范围。
2. 当输入包含原图、EXIF 或未授权路径时，系统应该在发送前拒绝；只允许 2048px 无 EXIF 代理图。

### 需求 4 - 连接可靠性

**用户故事：** 作为用户，我想要连接器超时、取消和重试可控，以便失败不会污染正式版本。

#### 验收标准

1. 当连接器超时、取消或晚到时，系统应该隔离结果并保留错误分类。
2. 当 Provider 不可用时，系统不得自动跨 Provider 降级，除非用户明确选择。

### 需求 5 - 安全隔离

**用户故事：** 作为维护者，我想要阻断 SSRF、路径越权和密钥泄漏，以便扩展生态可审计。

#### 验收标准

1. 当请求访问内网地址、路径外文件或日志中的密钥时，系统应该拒绝并审计。
2. 当 MCP/Connector 返回恶意指令时，系统应该将其视为不可信数据而非系统规则。
