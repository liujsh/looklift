# 需求文档

## 简介

为 LookLift 提供与 Agent Runtime 配套的设置、插件、运行详情和恢复界面，让全局规则、记忆、扩展权限、运行事实及用户确认边界都可见、可控、可审计。

## 需求

### 需求 1 - 全局规则与记忆设置

**用户故事：** 作为用户，我想要管理全局规则、事实、偏好和项目上下文，以便每次 Agent 对话都遵循稳定且可解释的上下文。

#### 验收标准

1. 当用户打开设置页时，系统应该分别展示全局规则、记忆条目和项目上下文，并显示来源、更新时间、确认状态和版本摘要。
2. 当外部 Connector 或 Agent 提议写入记忆时，系统应该以 Proposal 形式展示差异，用户确认后才允许应用。
3. 当规则存在冲突时，系统应该显示优先级和冲突原因，不得静默覆盖用户内容。

### 需求 2 - 插件管理与能力授权

**用户故事：** 作为用户，我想要浏览、安装和管理插件，并逐项授权能力，以便扩展功能而不扩大数据权限。

#### 验收标准

1. 当用户查看插件时，系统应该展示来源、版本、摘要、任务类型、请求能力、数据接收方和风险。
2. 当插件请求能力时，系统应该支持逐项授予、拒绝、撤销和重新授权，并显示当前生效范围。
3. 当插件校验失败、被撤销或版本不兼容时，系统应该阻止启用并给出原因。

### 需求 3 - 运行详情与候选审阅

**用户故事：** 作为用户，我想要查看一次运行的完整轨迹和候选差异，以便理解 Agent 做了什么并决定是否接受结果。

#### 验收标准

1. 当运行详情页打开时，系统应该展示 Harness、Provider、模型、Skill、Template、上下文快照、工具调用和错误分类。
2. 当候选生成时，系统应该展示预览、参数差异、亮度/裁切指标、Revision 和 Verifier/Critique 结果。
3. 用户未确认前，候选不得自动写入正式版本、导出或进入批量执行。

### 需求 4 - 中断运行恢复

**用户故事：** 作为用户，我想要在应用重启后恢复中断运行，以便继续工作而不会重复调用或覆盖新编辑。

#### 验收标准

1. 当存在 `interrupted`、`cancelling` 或 `stale` 运行时，系统应该在恢复中心列出状态、原因、最后一致事实和基线差异。
2. 当用户选择继续时，系统应该明确创建新的 Attempt，并在必要时要求重新选择 Harness/Provider。
3. 当正式基线已变化时，系统应该只允许查看旧候选或重新开始，不得直接应用旧候选。

### 需求 5 - 可访问性与隐私提示

**用户故事：** 作为隐私敏感用户，我想要在关键操作前看到数据和权限提示，以便做出知情确认。

#### 验收标准

1. 当数据即将发送给外部 Provider 或 Connector 时，界面应该显示脱敏范围、接收方和取消入口。
2. 当用户取消、拒绝或关闭页面时，系统应该保持正式版本不变，并保留可审计事件。
