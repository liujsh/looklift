# 需求文档

## 简介

为 LookLift 增加可编辑、可确认、可追踪的全局规则、Memory 和项目上下文，使模型 API 与本地 CLI 在每次运行前消费同一份可复现上下文。该模块不允许用长期记忆绕过系统安全边界，也不允许从普通聊天中静默写入用户记忆。

## 需求

### 需求 1 - 全局规则

**用户故事：** 作为摄影用户，我想维护长期有效的修图规则，以便每次运行都遵守我的工作边界。

#### 验收标准

1. 当用户创建、编辑、停用或删除一条规则时，系统应该保存规则类型、作用域、版本、来源、确认状态和内容 Hash。
2. 当规则属于系统安全边界时，系统应该拒绝用户或模型覆盖该规则。
3. 当当前目标与软性全局规则冲突时，系统应该向用户展示冲突并要求确认本轮覆盖。

### 需求 2 - 记忆树

**用户故事：** 作为摄影用户，我想按事实、偏好、项目和反馈管理记忆，以便控制 Agent 能长期使用哪些信息。

#### 验收标准

1. 当用户打开设置页时，系统应该按类型展示可编辑的 Memory 条目及其来源、更新时间和确认状态。
2. 当 Agent 从对话、Connector 或照片项目中发现可长期保存的信息时，系统应该生成待审核 Proposal，而不是直接写入正式 Memory。
3. 当用户拒绝或删除 Memory 时，系统应该阻止后续新 Run 注入该条目，但不修改已冻结的 Run 快照。

### 需求 3 - 项目上下文

**用户故事：** 作为摄影用户，我想为一个项目保存照片集合、目标、参考风格和输出要求，以便多次运行保持一致。

#### 验收标准

1. 当用户选择项目上下文时，系统应该记录项目 ID、来源、作用域和内容 Hash，并允许本次 Run 单独取消使用。
2. 当同一项目启动新的 Attempt 时，系统应该优先使用已确认的项目上下文快照，而不是读取未确认的最新草稿。
3. 当项目上下文包含原图路径、EXIF 或密钥时，系统应该在进入外部 Harness 前拒绝或脱敏。

### 需求 4 - 上下文可解释性

**用户故事：** 作为用户，我想知道 Agent 为什么使用或忽略某条规则/记忆，以便审查它的判断依据。

#### 验收标准

1. 当 Domain Pack 编译完成时，系统应该记录实际使用、压缩和省略的来源列表及原因。
2. 当用户查看运行详情时，系统应该展示规则、Memory、项目上下文、Skill 和 Template 的来源及版本。
3. 当上下文预算不足时，系统应该按预定义优先级省略低价值 Reference，不得截断安全边界、用户目标和已确认规则。

### 需求 5 - 隐私与自动提取

**用户故事：** 作为用户，我想控制记忆自动提取和数据来源，以便长期上下文不会收集我未确认的敏感信息。

#### 验收标准

1. 当应用首次运行或未配置自动提取时，系统应该默认关闭聊天自动写入 Memory。
2. 当 Memory 来源为外部 Connector 或模型提取时，系统应该保留来源标识并要求用户确认。
3. 当 Memory 被注入 API 或 CLI Harness 时，系统应该只发送必要的脱敏文本，不发送用户 Home、数据库和原图路径。
