# 实施计划

> 状态：实施中。2026-09-12。
> 配套：[需求](requirements.md)、[设计](design.md)。复选框只在对应代码、离线测试与必要接线均完成后勾选。
> 实施完成条件：按 A → B/C → D → E 收口；真实平台和外部仓库步骤必须保留人工验收状态，不能用 Fake 测试替代。

## 本轮已完成的可验证切片

- [x] 扩展现有 `PluginRegistry`：Manifest 别名/摘要、版本化工具目录、原子持久化与历史兼容。
- [x] 新增按项目隔离、可持久化的 `CapabilityGrantStore`，修复插件列表跨项目合并授权。
- [x] 实现字段加权中文召回、分页短摘要、完整 Schema 激活、唯一 Provider 别名、Schema Hash 与活动集 revision。
- [x] 实现统一 Plugin Tool Gateway；桥接参数使用完整 Draft 2020-12 Schema 校验，目录或授权变化立即失效。
- [x] 实现受控 stdio MCP Client：握手、分页 `tools/list`、目录上限、审核白名单、`tools/call`、超时与进程回收。
- [x] 实现 `PLUGIN_TASK` 的零图/多图输入、CLI 隔离工作区和 OpenAI-compatible 请求投影。
- [x] 实现匿名 Asset Broker 与持久化 Action Gate；外写先确认、revision 变化失效、确认原子消费、未知结果禁止盲重试。
- [x] 插件发现/描述接入 Python GUI API；压缩历史时保持 Tool Call/Result 配对。
- [x] 实现经用户确认的本地 ZIP 安装：固定包摘要、许可/平台/依赖/文件清单校验，阻断路径穿越、重复路径、符号链接与压缩炸弹，并原子落到版本目录。
- [x] Connector 配置与授权可重启恢复；进程重启后强制回到未连接，避免把历史状态伪装为在线。
- [x] OpenAI-compatible 与 Pi 复用同一任务策略：插件任务可发现、描述、动态原生投影或固定桥接，并以待确认 Action/本地草稿结束，不要求候选终态。
- [x] Action 增加有效期、取消和启动恢复；宿主重启时执行中外写收敛为结果未知。
- [x] 实现受管 Streamable HTTP MCP Client：仅回环地址、Bearer/Origin、JSON/SSE、协议版本与 Session ID、无重定向、响应上限和显式会话关闭。
- [x] 实现签名目录供应链内核：Ed25519 多公钥/撤销、有效期、防 revision 回滚、离线缓存、固定 HTTPS 包摘要下载，并把目录身份/版本/许可证绑定到原子安装器。
- [x] 实现目录专用真实 HTTPS Fetcher：显式主机白名单、公网 DNS 校验、无环境代理/重定向和流式响应上限。
- [x] 实现 Connector 会话生命周期协调：Transport 启动后握手/刷新才上线，失败关闭半成品连接，断开/撤销先收敛权威状态；连接增加 Workspace 内独立账号身份。

仍未完成：应用内正式目录公钥及轮换发布、真实目录服务、生产 Connector 工厂与凭据/profile 清理、HTTP SSE 断线续传及服务端反向消息、其他 CLI 契约验证、统一 tokenizer/Skill/Result 预算、通用插件 UI、独立小红书包及真实平台人工验收。因此下方阶段任务保持未勾选，不能把本轮 Fake/契约通过等同最小演示完成。

## 阶段 A — 通用插件基础与任务边界

- [ ] A1. 实现版本化 Manifest 与持久化安装/连接目录。
  - 工具身份、审核风险、输入映射、Skill/Reference、包依赖与兼容信息。
  - 修复插件授权查询跨项目合并，统一 Grant、Token、凭据引用与撤销权威。
  - 验证第二个 Fake 插件无需核心平台分支即可接入。
  - _需求：需求 1、需求 7、需求 8_
- [ ] A2. 实现 PLUGIN_TASK 输入与终态策略。
  - 支持文字或多张安全图、正式成片选择与任务关联；不扩大 PHOTO_EDITING 权限。
  - 从 API/Pi 的候选专属逻辑中拆出共享循环/生命周期和任务策略，不新增第二套 Agent Loop。
  - 分离发现、执行、模型与等待确认预算。
  - _需求：需求 2、需求 5、需求 9_
- [ ] A3. 实现受控 MCP Client 与进程生命周期。
  - 协议协商、分页目录、超时取消、stdio 与受管本地 HTTP、账号隔离。
  - Schema校验、目录复杂度上限、工具变化处理；明确非沙箱信任边界。
  - _需求：需求 5、需求 7、需求 8_

## 阶段 B — 意图召回与渐进暴露

- [ ] B1. 建立本地插件摘要/工具索引与发现接口。
  - 先权限过滤，再中文别名/全文检索；显式平台优先，支持无命中、歧义和分页回退。
  - 可发现、已加载、可调用、待授权等状态分离；安装目录建议不形成执行权限。
  - _需求：需求 3、需求 4_
- [ ] B2. 实现 Exposure Planner 与统一预算。
  - 小集合直接加载，大集合发现/描述；唯一工具别名、Schema Hash与活动集revision。
  - 工具、Skill、结果、历史及图片共同计量；保留调用配对和未决Action。
  - 以合成规模集固定阈值，拒绝超大必需Schema，不截断结构。
  - _需求：需求 4、需求 10_
- [ ] B3. 实现 API Schema 投影与通用桥接两条调用路径。
  - API在下一轮刷新tools；桥接先描述再调用；原生与桥接共用执行守卫。
  - Provider Schema不兼容时明确回退或失败；禁止丢弃参数约束。
  - _需求：需求 4、需求 5、需求 7_
- [ ] B4. 接入 Pi 通用 Extension，逐个验证其他 CLI。
  - 替换现有两工具数量检查与候选专属成功判断。
  - Claude Code/Codex使用会话级受控代理；验证配置隔离、禁绕过、确认等待、历史预算。
  - 未通过契约测试的CLI标明限制；不更改用户全局MCP配置，不借用任意Shell回退。
  - _需求：需求 5、需求 10_

## 阶段 C — 素材、Skill 与用户确认

- [ ] C1. 实现通用 Asset Broker 和插件资源读取。
  - 冻结选图、正式版本、匿名引用和内容Hash；多图安全预览与预算。
  - 受限字段映射和临时导出素材；Reference按需读取、来源和权限校验。
  - _需求：需求 2、需求 6、需求 7_
- [ ] C2. 实现通用 Action 草稿与确认执行状态机。
  - 模型发起外写只生成待确认Action，不上传；UI修改后重新冻结参数。
  - 绑定账号/素材/内容/时间/可见性/版本/工具，原子消费确认；跨项目与并发隔离。
  - 拒绝、过期、撤销、结果未知、崩溃恢复；不自动重发无幂等保证的写入。
  - _需求：需求 6、需求 7、需求 9_
- [ ] C3. 完成通用插件页与聊天入口。
  - 官方目录、已安装、连接状态、能力与来源详情、升级/停用/清理入口。
  - 从真实选图发起一句话任务；按声明式元数据呈现完整确认卡。
  - UI区分本地草稿、平台上传、平台草稿和发布；不写小红书特定组件。
  - _需求：需求 2、需求 3、需求 6、需求 8_

## 阶段 D — 首个独立插件包与分发

- [ ] D1. 在独立插件工作区制作小红书包，先完成离线内容。
  - 固定上游完整提交、许可证与传递依赖；验证18工具快照及实际Schema。
  - 编写看图配文案Skill、平台Reference、素材/账号字段映射、风险元数据。
  - 本地草稿使用宿主通用Action；发布结果无法确认时保留未知，不捏造链接。
  - _需求：需求 1、需求 6、需求 9_
- [ ] D2. 建立可校验目录与Release安装链路。
  - 源码仓库、Release资产、签名目录、公钥轮换、缓存和撤销策略。
  - 测试离线缓存、包篡改、路径攻击、依赖漂移、版本回滚和历史快照。
  - 本地包验证完成后，再经仓库所有者授权创建/发布GitHub仓库与Release；未上架不能显示为可安装。
  - _需求：需求 8、需求 10_
- [ ] D3. 人工验证小红书登录与一次图文工作流。
  - 用户选择账号和素材；实际上传/发布前确认最终内容，记录平台和包版本。
  - 验证账号切换、会话清理、拒绝、超时及无回执；不把私密发布当草稿。
  - 未通过人工发布验收时，只标记实验性，不能宣称正式支持。
  - _需求：需求 6、需求 7、需求 9、需求 10_

## 阶段 E — 收口与后续

- [ ] E1. 离线评估并收口。
  - 对比全量/预选/渐进方案的累计token、召回、正确率、耗时和完成率。
  - 安全与状态机test-first；粘合代码写通后补契约测试；成型代码diff自审一次，不派子代理。
  - 迭代仅运行受影响测试；有代码改动时按仓库要求收口验证，前端最终一次 `pnpm test && pnpm build`。
  - 实现后回填architecture与开发日志，保留尚未通过的CLI/平台人工验收项。
  - _需求：需求 1、需求 4、需求 5、需求 7、需求 9、需求 10_
- [ ] E2. 后续能力独立验收。
  - 平台草稿先验证上游分支许可、实现、持久化及手机同步，再决定是否维护最小补丁。
  - 抖音优先比较账号可用的官方接口与浏览器适配；复用宿主，不新增核心平台分支。
  - 动态原生CLI工具集、向量检索、远程MCP和硬沙箱仅在明确需求及测量支持时推进。
  - _需求：需求 1、需求 5、需求 8、需求 10_

## 依赖顺序与最小可演示交付

A → B/C → D → E；B与C共享A契约，单智能体按连贯模块顺序实现。

最小演示必须同时具备：真实插件包、按需发现、API及Pi至少各一条一致调用路径、看图文案、可编辑确认、未确认零外发、正确结果展示和停用。仅有插件卡片或工具列表不能计为完成；其他CLI支持以各自验收为准。
