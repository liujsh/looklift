# RAW 可行性门设计

## 状态归属

RAW 门是一次性离线诊断工具，不进入 Studio 运行时。Python 核心模块拥有样本解析、解码适配、测量和决策；CLI 只负责参数入口与报告落盘。

## 输入与输出

输入为 JSON manifest：每项包含本地 `path` 和作者提供的 `camera` 标识，可选 `label`。工具只读这些路径。

输出为 JSON report 和中文文本摘要。每个样本记录状态、相机标识、格式、尺寸、通道、位深、解码耗时、峰值内存、方向/白平衡检查和错误码；顶层记录 rawpy 可用性、样本覆盖、管线兼容性、GO/NO-GO 与建议后续路径。

## 解码与管线边界

- rawpy 是可选运行时依赖；导入失败必须转为结构化 `rawpy_unavailable`，不在模块导入阶段让 GUI 崩溃。
- 解码适配层只把 RAW 转成现有预览入口能消费的 RGB 数组/图像，不修改 `analysis` schema、渲染签名或 sidecar 写入契约。
- 方向、通道顺序和白平衡检查使用离线确定性规则；测量失败只影响当前样本，不中断整份报告。
- 内存测量优先使用 Windows 可用的进程峰值接口；平台不支持时记录 `unavailable`，不伪造数值。

## 决策规则

GO 必须同时满足：rawpy 可用、样本覆盖达到要求、所有必测样本成功解码、输出满足 RGB/位深/方向契约、代表性结果能进入现有预览链路，且性能/内存没有超过门禁阈值。任一条件失败即 NO-GO，并把 v2.3-B 锁定为内嵌 JPEG 预览 + XMP sidecar 降级路径，直到作者重新运行门禁。

## 停止条件

输入、输出、失败隔离、决策和降级路径无矛盾即停止；精确字段类型、测量采样方式和替身形状由测试固定。
