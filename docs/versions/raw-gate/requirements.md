# RAW 可行性门需求

## 目标

在实现 v2.3-B 设备导入前，用本地 rawpy 探针验证常见相机 RAW 是否能稳定进入 LookLift 的白盒调色链路，并给出可审计的 GO/NO-GO 结论。

## 范围

- 接受作者提供的离线样本清单，覆盖 5–10 种常见相机，至少包含 24MP 与 40MP 级别样本。
- 验证 rawpy/LibRaw 解码成功率、输出尺寸/通道、位深、方向、相机白平衡和 sRGB 转换结果。
- 记录单文件解码耗时、峰值内存和失败原因，生成机器可读报告与中文摘要。
- 用代表性解码结果经过现有 float32 预览/渲染入口，确认不会改变白盒参数契约。
- 明确 v2.3-B 的两条后续路径：通过则 RAW 全解码；不通过则使用嵌入 JPEG 预览与 XMP sidecar。

## 非目标

- 不在本门实现图库、设备发现、文件复制或导入 UI。
- 不触网、不调用 AI/provider，不把原始 RAW 上传到任何外部服务。
- 不把相机样本、解码缓存或测量产物提交到仓库。
- 不承诺 Lightroom/Adobe 的像素级一致，只验证进入现有白盒管线的必要条件。

## 验收

- 无 rawpy 环境能输出明确的 `NO-GO` 和安装/环境提示，而不是导入异常栈。
- 有样本时每个文件都有成功或失败记录，单个坏文件不吞掉其余结果。
- 报告包含样本身份、解码测量、管线兼容性、决策和降级路径；重复运行不改源文件。
- 自动化测试全程使用离线替身，不依赖 rawpy、真实相机文件或网络。

## 验收结果（2026-07-27）

8 种相机的 24–61MP CC0 RAW 样本全部成功解码为 16-bit RGB，并通过 float32 渲染边界、
方向、相机白平衡、性能与内存门禁。最终结论为 **GO**，v2.3-B 采用 RAW 全解码路径。
