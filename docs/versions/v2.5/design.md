# v2.5 自动化技能设计

## 状态归属

Python 引擎拥有技能定义、执行计划、运行记录和文件输出；React 只维护未提交的表单选择并消费
显式计划与任务状态。技能引用现有 look 名称，执行计划在确认时冻结对应 `analysis` 与强度，
因此执行期间风格库变化不会改变本次结果。

## 技能与计划

首版技能包含名称、look 名称、强度、输出文件名后缀和 JPEG 质量。技能以应用数据目录中的独立
JSON 保存，不改变用户 look 文件。计划接收技能、输入文件列表和输出目录，规范化并检查：

- 输入是真实文件且扩展名属于当前引擎支持集合；实际解码失败由执行阶段逐项隔离；
- 输出始终位于用户选择的目录，扩展名为 `.jpg`；
- 同批输出名不冲突，且磁盘上不存在同名文件；
- 输出路径不等于任何输入路径。

计划返回逐文件状态和冻结参数；前端使用首个可执行项目及现有预览接口展示实际效果。存在冲突
或无效输入时不能开始执行，用户需先调整选择或输出规则。

## 执行与恢复

后台任务按计划顺序逐张渲染，先写同目录临时文件，再原子替换为最终的新文件。每项完成后原子
更新应用数据目录中的运行清单。取消采用协作式边界：正在渲染的单张允许完成，随后不再开始新
项目；剩余项目标记为取消。进程异常退出时，遗留的运行中项目在下次读取时转为“中断”，可与
失败项一起重试。

重试复用运行清单中冻结的 `analysis`，只选择失败、中断或取消项；已经成功的输出永不重复写。
若重试前目标路径已存在，则该项保持失败并给出冲突原因。

## API

- `GET/POST /api/automation/workflows`：列出或创建技能。
- `DELETE /api/automation/workflows/<id>`：删除技能定义，不删除历史输出或运行记录。
- `POST /api/automation/plans`：生成带冻结参数的待确认计划。
- `POST/GET /api/automation/runs`：确认计划并启动；列出近期运行。
- `GET /api/automation/runs/<id>`：轮询持久化运行状态。
- `POST /api/automation/runs/<id>/cancel`：请求协作式取消。
- `POST /api/automation/runs/<id>/retry`：仅重试失败、中断或取消项。

## 安全与兼容

- 名称、路径、范围和 analysis 均在后端校验，前端不能通过拼路径绕过输出规则。
- 不覆盖任何已存在文件；失败只清理本次临时文件。
- 自动化核心不依赖 HTTP 或 React，CLI/其他壳以后可复用同一实现。
- 现有 `looklift.batch` 的“按目录共同分析”语义保持不变；本期成片自动化使用独立模块，避免
  把两个不同业务堆进同一文件。

## 停止条件

技能、计划确认、非覆盖输出、取消和失败重试契约无矛盾即停止；精确清单字段与轮询间隔由测试固定。
