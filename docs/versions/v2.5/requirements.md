# v2.5 自动化技能需求

## 目标

让用户把已有白盒风格保存为可复用的自动化技能，对明确选择的一组本地照片先预览影响范围，
再批量生成独立成片；单张失败不阻塞后续照片，任务可取消、可恢复并只重试失败项。

## 用户故事

| 编号 | 用户故事 | 本期交付 |
|---|---|---|
| U34 | 想把常用风格变成可重复使用的批处理 | 保存“风格、强度、输出后缀和 JPEG 质量”为自动化技能 |
| U35 | 批量执行前想确认会处理什么、输出到哪里 | 展示首张效果预览和逐文件输出计划，用户确认后才执行 |
| U36 | 大批量中少数照片失败时不想全部重来 | 逐项记录成功、失败和取消状态，重启后可只重试失败项 |

## 验收标准

- [ ] “自动化技能”页可创建、选择和删除技能，技能只引用已有白盒风格。
- [ ] 用户明确选择输入照片和输出目录；执行前展示输入、输出、冲突与首张效果预览。
- [ ] 输出固定为新 JPEG 文件，默认添加后缀，不覆盖原文件或已存在文件。
- [ ] 执行时逐张更新进度；单张失败不阻塞后续照片。
- [ ] 取消后不再开始新照片，已成功文件保留，临时文件不残留。
- [ ] 运行记录持久化；应用重启后可查看结果并只重试失败或中断项。
- [ ] 执行使用与 Studio 相同的 `analysis`、强度缩放和渲染引擎，不建立第二套参数模型。
- [ ] 自动化测试完全离线，不调用真实 AI/provider，不写真实用户目录。

## 非目标

- 不执行任意 Python、Shell、JavaScript 或第三方插件代码。
- 不在首版把真实 AI/provider 调用放入批任务，避免不可预估的网络结果、费用与隐私影响。
- 不覆盖、移动或删除原照片，不实现目录监控和无人值守触发。
- 不做分布式队列、GPU 调度、十万级任务或云同步。
- 不在本期提供 RAW 高位深成片；输入沿用当前渲染引擎可解码格式。
