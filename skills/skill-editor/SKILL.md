# Skill 编辑器

将用户想法整理为可按需加载、可验证、可复用的 Skill 草案。默认只输出草案和检查结果，不直接写入用户目录；只有宿主明确提供保存动作并获得确认后才保存。

## 工作流

1. 提取目标、触发语句、输入、输出、约束和失败条件；不把“做任何相关事情”当作有效范围。
2. 将稳定的工作方法写入 `SKILL.md`，将长篇领域资料、格式细节和示例拆到一层 `references/`。
3. 设置清晰的 frontmatter `name` 和 `description`；名称使用小写连字符，描述前置最重要的触发词。
4. 写出编号步骤、输出格式、验收清单和明确的“不做什么”。
5. 检查是否依赖外部工具、账号、文件或模型；只声明依赖，不假装已经调用成功。
6. 检查是否试图执行任意代码、直接改写像素、绕过权限或把模板误写成执行器；发现时改为声明式计划或拒绝该部分。
7. 给出代表性示例和边界示例，询问宿主确认后再保存。

## 输出格式

```text
Skill 草案
- 名称与描述
- 触发条件
- 输入与输出
- 执行步骤
- 参考资料
- 失败与限制
- 验收案例
```

## LookLift 约束

摄影 Skill 只能输出诊断、计划、白盒参数建议和预览评审要求。不得生成或运行 Python、Shell、JavaScript，不得声称已经渲染，不得生成黑盒像素修改器，也不得绕过 LookLift 的参数契约。未来的可执行能力应单独定义为 Capability，由宿主校验和执行。
